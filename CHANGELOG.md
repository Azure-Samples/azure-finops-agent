# Changelog

All notable changes to **Azure FinOps Agent** are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Add optional encrypted CI diagnostics for failed live evaluations. With repository variable `EVAL_DIAGNOSTICS_CERT` set to a maintainer's public certificate, a failed run's artifact gains `private-diagnostics.enc.json`: the failed-case judge rationale, answer, gate failures, bounded tool details and unfinished captures, encrypted with RSA-OAEP-256 wrapping an AES-256-GCM key. Public summaries still withhold internal-test answers and rationale. `tests/LiveEvaluations/New-DiagnosticsCertificate.ps1` creates a non-exportable RSA 4096 key in the Windows user certificate store, and `Unprotect-Diagnostics.ps1 -RunId <id>` downloads and decrypts a run. Forks do not inherit the variable, so they never encrypt their tenant data to the upstream key.
- Add hosted web search, on by default (`AzureOpenAI:WebSearch`; Bicep parameter `aoaiWebSearch` from `AZURE_OPENAI_WEB_SEARCH`, default true; evaluator `EVAL_WEB_SEARCH`, defaulting to the same value so the live gate tests what deploys). The system prompt limits it to recent public information that no API returns (announcements, new models, features or regions) and requires a source URL and date for each web fact; tenant data, list prices, API contracts and Learn pages still come from `QueryAzure`. Search queries go to Bing grounding, which is outside the Azure data boundary; set `AZURE_OPENAI_WEB_SEARCH=false` (or `AzureOpenAI__WebSearch=false`) to keep every call inside it. Verified on the test slot with gpt-6-sol: a question about this week's Foundry announcements ran seven web searches and answered with a dated, cited source.
- Add stateless LINQ cropping to `QueryAzure` (System.Linq.Dynamic.Core 1.7.4) in place of a stored-response database. A response up to 32 KB returns whole; a larger one returns its coverage fields and the C# schema inferred from its JSON (names, types, counts, samples and a starter expression), and the model repeats the request with `query`, a C# LINQ expression over the response root, receiving only its result (up to 48 KB) beside the response's own coverage line. Column/row tables become row objects and text becomes `lines`. Several url lines share one `query`, with a schema common to several large responses shown once. `query` without `url` is a calculator over copied figures that sends no request and is never source evidence. The sandbox allows only LINQ, string, `Math`, `Convert`, date and primitive members, meters every enumeration (20M steps, 10 seconds, 64K-character strings), and evaluates a root-only aggregate inside a lambda once, so a per-item share of total stays linear. Nothing is stored between calls and the application keeps no database.
- Add `ApplyAzureChange`, an Agent Framework `ApprovalRequiredAIFunction` and the only ARM PUT/PATCH path. The UI shows the held call's exact method, URL and body; the next chat turn carries `approval: {requestId, approved}`, and only an explicit approval runs it. Any other message rejects every held change (shown as "not applied (a new message was sent instead)"), a stale approval returns `approval_stale` without sending, and an approved change whose turn was interrupted is never re-approved. A 201/202 result is accepted, not complete: the model polls the returned `Azure-AsyncOperation` or `Location` URL.
- Add a post-deployment chat gate to the feature and production workflows. The live evaluations call the model with the evaluation identity, so build 168 passed all 20 cases while the test slot's own managed identity lacked Foundry User (`agents/write` HTTP 403). Each deployment now records the prior image and model settings, sends one real anonymous chat turn through the deployed URL and requires a completed answer. On failure it restores the prior state and fails the run.
- Add optional `AZURE_PREVIEW_SLOT_NAME` provisioning. [infra/modules/preview.bicep](infra/modules/preview.bicep) creates a preview deployment slot on the production web app and plan, with the web app's configuration and its own managed identity, which gets AcrPull and Foundry User. Optional `AZURE_PREVIEW_DEPLOY_SUBJECTS` adds a GitHub OIDC deploy identity: Website Contributor on the slot only, Reader on the parent and AcrPush. The feature workflow's Azure jobs use GitHub environment `test`, so one subject serves every branch. Postprovision registers the slot's OAuth redirect URIs and federated credential, no longer recreates an identical production credential, and prints the workflow settings. Preprovision rejects a Basic plan, which ARM preflight accepts but which fails mid-deployment. Existing role-assignment names are unchanged.
- Add an "AI & LLM pricing" menu with ten questions, chosen from what users ask (in 100 audited conversations: per-1M token comparisons in 6 sessions, PTU monthly cost and reservations, the newest model's list price, token-based project estimates and model speed). It covers the newest Foundry models and prices, prices by deployment type (Global, Data Zone, Priority Processing; short and long context), the existing GPT-4o/GPT-4.1 token comparison, open and partner models, a chatbot monthly estimate, PTU hourly versus 1-month and 1-year reservations, cached-input and Batch savings, a RAG embeddings plus AI Search estimate, image, speech and realtime prices, and the latest published benchmarks next to price. Signed out, the navigation shows it expanded and "Infrastructure pricing" (the previous public pricing prompts) collapsed. Signed in, both start collapsed below the maturity cards, and infrastructure pricing lists the personalised prompts first. All public prompts remain in `pricingCategory.publicPrompts`, so the curated live-evaluation cases keep their IDs.

### Changed

- Answer "current billing period" questions for the billing period. Asked for budgets against actual spend "for the current billing period", the model queried a custom calendar range (the first two days of the month) and never established the billing period, so the live gate judged the answer incomplete. The Cost Management guidance now states that the current or last billing period uses timeframe `BillingMonthToDate` or `TheLastBillingMonth`, which the service resolves to the scope's billing period, while `MonthToDate`, `TheLastMonth` and `Custom` are calendar periods (Query API `TimeframeType`, Cost Management 2026-06-01). It also asks the model to say when a budget's own reset period differs.
- Fix Foundry model price lookups for the newest models. The system prompt said every token meter is priced per 1K tokens and told the model to multiply by 1000 and filter one product on 'glbl'. GPT-5 and GPT-6 meters are published per 1M tokens under their own product names ('Azure OpenAI GPT5', 'Azure OpenAI GPT6'), with Std Gl, Std DZ, PP (Priority Processing), Cd Inp (cached input), Cd Wr (cache write) and ShortCo/LongCo in the meter name. The rule would have missed them or overstated them 1000-fold. The prompt and the `QueryAzure` description now name each model family's product, the PTU hourly and reservation rows (a reservation's price covers its whole term even though the unit reads '1/Hour') and the newer meter abbreviations. They convert to per-1M rates with `retailPrice * (unitOfMeasure == "1K" ? 1000 : 1)`, and they answer "newest models" questions from one call that keeps each family's latest-dated meters. The price list is the evidence for which models have prices, so a pricing question needs no web search or documentation lookup. Benchmark, speed and latency questions are answered directly: one web search for the latest published results while the prices load in parallel, with each figure's source, date and whether it is vendor-reported. In local runs with gpt-6.1-sol, all ten AI pricing questions answered without a clarifying question. The GPT-4o comparison made one call and no web search, and the benchmark question went from 10 calls to 6 with no documentation lookups.
- Simplify the layout so there is one New chat and history works on phones. Three New chat buttons were visible at once (top bar, navigation and the Conversations panel). The conversation list and scheduled jobs sat in the right sidebar, which is hidden at 900 px and below, so phone users could not reach them. The left navigation now holds New chat, the prompt library, Scheduled jobs and Chats. The right sidebar shows only Agent execution, and only while a conversation has tool calls. The top bar shows an icon-only New chat only while the navigation is hidden, so exactly one is visible at any time.
- Shorten maturity assessments and answers, which makes them faster. Production Crawl turns took 100-127 s, and about 85% of that was the model writing roughly 8,000 output tokens at 50-100 tokens/s, with time to first token near 1 s throughout; tool calls took about 20 s. Each `ReportMaturityScore` dimension `detail` is now at most 20 words of decisive figures (the score card showed 40-60-word notes). The maturity answer is about 150 words plus one table of at most five rows, and it no longer restates the dimensions the score card already shows. Other answers aim for 150-250 words plus their one visual, stating each fact once without dropping a requested metric or required qualifier.
- Show each tool call's own execution time. Parallel calls' results reach the stream together once the whole batch finishes, and the duration was measured from when the model wrote each call, so every call in a batch showed the same time (for example 15.2 s for calls that took 1-15 s). The function invoker now records each call's execution time, `ToolCompleteEvent.DurationMs` persists it, and `tool_done.durationMs` reports it.
- Keep long conversations fast. The chained Responses context keeps every earlier tool result, and production telemetry showed that model calls above about 180k input tokens waited 10-17 s for their first token, against about 1 s below 100k, even with 99% of the input cached. One three-hour conversation grew to 289k tokens, and one Crawl turn added 130k. When a completed turn's largest model input exceeds 100k tokens (`AgentConversation.CompactAfterInputTokens`), the next turn starts a fresh model context. It carries a bounded recap of the visible exchanges: user questions without injected context and assistant answers, newest first, up to 24,000 characters (4,000 per message), with tool results left out, so the model queries again for figures the answers do not show. A pending approval postpones compaction because it must be answered in the context that proposed it. The UI transcript is unchanged. A turn that starts a fresh context, through compaction or an expired response chain, now receives the connection and uploaded-file context again; before this, both were sent only once per session. Scheduled jobs keep their compaction every 20 runs.
- Render answers with a real Markdown renderer ([markdown.js](src/Dashboard/frontend/src/markdown.js)). It escapes the text first, then builds paragraphs, headings, nested and ordered lists, task items, block quotes, rules, fenced code, GFM tables with column alignment, http(s) links and autolinks (new tab, `noopener noreferrer`) and `prompt:` chips. Bold needs no surrounding spaces (`**Total:**USD`). Underscores inside identifiers such as `Standard_D4s_v5` and a lone `*` between spaces are never emphasis.
- Keep the model's reasoning summary visible. A new reasoning part (the next summary heading) now starts its own paragraph instead of running into the previous one. Each thinking segment is persisted as a `thinking` transcript event (`ReasoningEvent`), and the restored transcript returns it as the assistant message's `thinking`, so the reasoning summary survives reloads alongside its answer. Live streaming still uses the unpersisted `reasoning` deltas.
- Redesign the chat's progress and thinking UI after the AskMe app. One activity row replaces the assistant avatar, the typed intent line, the streaming cursor, the bouncing dots and the open reasoning box. It has three pulsing dots and a one-line, sentence-case status that sweeps in from the left. The status reads "Querying Cost Management", "Checking retail prices for Standard_D4s_v5 and 1 more" or the reasoning summary's latest heading. The reasoning summary itself sits above the reply in a "Thinking" section. It stays open while the model reasons or calls tools, collapses with a short animation to a one-line toggle as soon as the answer text starts, and can be reopened; completed and restored replies show it collapsed. The row sits below the streamed text and returns whenever the model goes back to tools or thinking. Cooldowns keep their own card. A reopened running turn and a reconnect share the same row, with the server's elapsed time and finished tool calls underneath. Status changes are not a live region. The motion stops for reduced motion and pauses in a hidden tab, and completed replies stay static. The UI now uses Google Sans Flex (SIL OFL 1.1, bundled under `src/Dashboard/frontend/src/assets/fonts` with its licence) in AskMe's flat setting: ROND 0, width 92. Other changes: replies are 17 px in `#1F1F1F` ink, user messages are rounded `#F4F4F4` bubbles, the composer is a soft rounded card with a black circular send/stop button, and notices and the cooldown card use quiet neutral panels. On narrow screens the composer actions are icons (their labels remain accessible names), so the send/stop button is no longer pushed off the edge.
- Clean up the whole UI to AskMe's design system while keeping the brand. [App.vue](src/Dashboard/frontend/src/App.vue) defines one set of colour, radius, motion and type tokens that every component uses. The 38 font sizes, 9 weights and 6 monospace stacks become five sizes (13 px caption, 15 px label, 17 px body, 19 px title, 23 px heading), weights 400, 500 and 600, one sans family (Google Sans Flex) and one `--font-mono` used only for code (tool snippets, the tool popover, script previews and code in answers). Decorative letter spacing and uppercase labels are gone, and charts use the same family and sizes. The top bar has the original blue gradient again, and the empty page keeps the original big, bold "Azure FinOps Agent" title with the gradient "FinOps", on hairline-bordered cards. One "New chat" action with AskMe's square-pen icon replaces the composer's "Clear" and the Conversations "+ New" (where it appears is described in the layout entry below). The message column and composer use more of the width. Maturity score cards use the new sizes and clamp each dimension's evidence to two lines, which expand on click. A new [AppIcon.vue](src/Dashboard/frontend/src/components/AppIcon.vue) supplies AskMe's outline icons as inline SVG. New rows in the execution, conversation and job lists slide in (disabled for reduced motion). Answer headings scale above the body text, and tables use the neutral tokens and scroll horizontally on narrow screens instead of clipping columns.
- Make the agent about three times faster per model round: the default reasoning effort is now `medium` (`appsettings.json`, the `Program.cs` fallback, Bicep `aoaiReasoningEffort`/`AZURE_OPENAI_REASONING_EFFORT`, the evaluator and the workflow's `EVAL_REASONING_EFFORT` fallback; the judge stays at `xhigh`). Production telemetry showed that model time was about 98% of every turn: a gpt-6.1-sol round at `xhigh` had a 35 s median, typical answers took 2-4 rounds (60-170 s), and a Crawl score took 10 rounds and 406 s, against 1-7 s of tool time. On the project Responses endpoint, one FinOps calculation took about 45 s at `xhigh`, 24 s at `high`, 14.5 s at `medium` and 11.7 s at `low`, and every level reached the same result; `low` saves little more than `medium` and risks tool planning. CI deploys the effort the gate tested, so the `ai-evaluation` environment's `EVAL_REASONING_EFFORT` is now `medium`.
- Next actions no longer cost a model round of their own. A response holding only `SuggestFollowUp` delayed every answer by a full round; the answer now ends with `[label](prompt:instruction)` links, which the UI already renders as buttons, and `SuggestFollowUp` is called only beside another answer-completing call (`ReportMaturityScore`, `RenderChart`, `GenerateScript`, `GenerateDataReport`). Maturity scoring makes any follow-up call in the `ReportMaturityScore` response and no other tool afterwards, so it no longer spends separate rounds on an unrequested `GenerateDataReport` and on `SuggestFollowUp` before answering. The upload-analysis prompts ask for links instead of a `SuggestFollowUp` call.
- The live-evaluation judge grades materiality, not polish (maintainer decision). It accepts an answer that is correct in substance and delivers every core requested result even when wording, depth or an optional caveat could be better, and still rejects wrong or unsupported material claims and missing core results. The deterministic gate now allows two failed calls, each corrected by a later successful call to the same tool, because the agent researches and self-corrects; a third or uncorrected failure still fails. The efficiency floor (3/5) and every case's time and tool budgets are unchanged.
- Switch the default agent model and live-evaluation agent/judge defaults from `gpt-6-sol` 2026-09-22 to `gpt-6.1-sol` 2026-09-29 (Bicep `aoaiModelName`/`aoaiModelVersion`/`aoaiDeploymentName`, `appsettings.json`, the `Program.cs` fallback and the evaluator). The production `gpt-6-sol` deployment kept running out of its 500-unit GlobalStandard quota; `gpt-6.1-sol` has its own model-specific quota, deployed at 1000 units (1M tokens/minute). Verified against the project Responses endpoint: `xhigh` reasoning with summaries, function calls, `previous_response_id` chaining, and hosted web search under `max_tool_calls`. gpt-6.1-sol does not support the Priority service tier, so `AZURE_OPENAI_SERVICE_TIER` must stay `Default`. Existing azd environments that set `AZURE_OPENAI_MODEL_*`/`AZURE_OPENAI_DEPLOYMENT_NAME` explicitly keep their values, and CI deploys the model in the `ai-evaluation` environment's `EVAL_MODEL`/`EVAL_JUDGE_MODEL`.
- The state root is configured by `AGENT_HOME`; the legacy `COPILOT_HOME` is still read as a fallback, and the default stays `/home/copilot` so existing conversations, identities and jobs are kept. Leftover Copilot SDK names in code and comments are gone.
- The live-evaluation judge now calls the same Foundry project Responses endpoint and token audience as the agent. `new Uri(endpoint, "/openai/v1/responses")` replaced the whole path, so a project endpoint silently became the account route with the Cognitive Services audience. Production run 36580876605 answered every case it ran, with tools, and still failed all of them on `Judge HTTP 500` after four retries while the agent's project route worked; the project route rejects the account audience with HTTP 401 naming `https://ai.azure.com`. Account endpoints keep the account route and audience.
- The live evaluation gate now stops at the first failed case in production as well as on feature branches (`EVAL_FAIL_FAST` is always `true`; the reusable workflow's `fail-fast` input is gone). Because the gate requires all 20 cases, the first failure already blocks deployment, and during the 2026-09-29 Sweden Central incident production runs spent about 25 minutes and a full round of model and Azure calls finishing 19 cases that could not change the outcome.
- A model response that ends without completing (no finish reason or usage) or reports a service error is now a failed turn with an explanatory error, not "No answer was returned", and the response chain stays on the last good response. During the 2026-09-29 Sweden Central Azure OpenAI/Foundry incident, a test-slot question started a hosted web search that never returned and the stream ended with no answer; the host saved that broken response as the chain head, so the next message ("hi") also came back empty. All three incomplete gpt-6-sol responses in the previous eight hours lacked a finish reason and usage, while all 20 completed ones had both.
- The live-evaluation judge now resends its unchanged request after a transient service or transport failure (HTTP 408, 429, 500, 502, 503, 504 or a dropped connection), at most four attempts, waiting 5, 10 and 20 seconds or the service's `Retry-After` up to 60 seconds within the judge's five-minute deadline. Production run 36558928032 (attempt 2) failed 19 of 20 cases on judge HTTP errors after the agent had answered: Sweden Central returned `InternalServerError: Unable to get resource information` and 408 timeouts to external callers while the app's managed identity kept receiving 200s. The agent's own model client already retried these; the judge did not. Request, authorization and verdict failures are never retried, and the gate's rules are unchanged.
- `QueryAzure` query reads are now as forgiving as JSON. Run 36541681695 stopped at 7 of 20 evaluations because 11 first-call queries failed on the query engine, not on Azure: five filtered an empty `value: []` whose items had no type, two called a method on a null `displayName`, one read `policyRule` that policy set definitions omit, one enumerated budget `notifications` (an object keyed by name), one projected a whole object over the output cap, and one passed a `double?` to `Math.Max`. A member absent from the response, null navigation, a missing key or index and an empty list now read as null or empty, and the result names the absent members; an object read as a collection becomes a dictionary of its merged values; a never-seen member used numerically is `double?`; `Math` accepts `double?`; and an object result over the cap trims its largest lists with a note instead of failing. Case-only member mismatches remain errors with the schema, unknown names are always data members, never types, and the sandbox's allowlist and step budget are unchanged. The nine logged queries are replayed as regression tests.
- A caveat the agent did not look up is now stated in general terms without figures. With the query failures fixed, run 36548093257's Blob tier comparison had no failed call and an efficiency score of 5, but the judge rejected it as ungrounded: permission to "name such a caveat without a lookup" became a table column of 30-, 90- and 180-day minimum storage durations that no call returned. The system prompt now says an unlooked-up caveat carries no number, duration, limit or table column.
- `RenderChart` now rejects chart data that is not a strictly valid, non-empty JSON array of objects or `[label, value]` arrays, returning an actionable error so the model resends it. Run 36481780607's Top 10 case failed because the model appended leaked format tokens after the array; the tool reported success, the browser could not parse the data and the promised chart never rendered. Data sent as a real JSON array is accepted as its text.
- Fix the test-slot deploy failing after a passing evaluation: model-settings JSON no longer carries `slotSetting`, which made `az webapp config appsettings set` rewrite the production site's `slotConfigNames` even for a slot-only write. The slot-scoped deploy identity is correctly denied that, so run 36479054161 passed all 20 evals and then stopped before changing the slot. Stickiness is left exactly as it is.
- The live-evaluation judge now counts waste and the host computes the efficiency score. The judge returns `avoidableCalls`, `avoidableRounds` and `avoidableSeconds`, naming each avoidable call, and `EvaluationGate.EfficiencyScore` applies the rubric's anchors: 5 no waste, 4 one or two avoidable calls or rounds, 3 more, 2 when waste roughly doubled the session (at least 0.75 times the necessary calls or seconds), 1 when it tripled it; 3 passes. Run 36475817429 failed an accepted, grounded and complete Idle sweep answer at score 2 for three redundant documentation lookups that added about 30 of 162 seconds, which the anchors put at 3. The threshold and waste definitions are unchanged; a search plus reading one of its results is now explicitly one lookup.
- The agent writes remediation script commands from knowledge and never searches documentation for script syntax. Its cleanup scripts re-check candidates by rerunning the Resource Graph KQL that already succeeded with `az graph query -q`.
- Cut the live-evaluation gate's wall time roughly in half. The suite runs in three lanes: every case that may query tenant-throttled Cost Management stays in one paced sequential lane, and curated cases that never need it (Advisor/Resource Graph/Graph/quota, and public pricing/calculation) run beside it. In CI each lane renews its OIDC login into its own temporary Azure CLI profile. Both deployment workflows now start the live suite alongside the credential-free regressions; deployment still requires both.
- The live-evaluation gate now allows the agent to research and self-correct. One failed tool call followed by a later successful call to the same tool, and one extra call to learn what to do (documentation, specification, api-version, schema or provider lookup), no longer fail a case or count as efficiency waste. A second failed call, a failure never corrected, a failed request resent unchanged, or an answer resting on failed evidence still fails. Five of the eight recent eval failures had answers the judge accepted as grounded and complete and failed only on tool-failure or efficiency rules; cases with two failures or an uncorrected final throttle still fail. The system prompt now matches: a failed call is information, so the agent reads its error and makes a better call instead of being told to avoid trial and error; it never resends a failing request unchanged or answers from a failed call.
- **Replace the GitHub Copilot SDK/CLI runtime with Microsoft Agent Framework** (`Microsoft.Agents.AI.Foundry` 1.22.0-preview.260918.1). One `AIProjectClient.AsAIAgent(ChatClientAgentOptions)` agent calls the Foundry project Responses API; each turn adds the owner's plain `AIFunction` tools through `ChatClientAgentRunOptions`, and independent calls run concurrently. Agent Framework's `FunctionInvokingChatClient` invokes them directly; its `FunctionInvoker` hook only normalizes model argument quirks. The UI, SSE contract and ownership checks are unchanged.
- `AzureOpenAI:Endpoint` is now the Foundry project endpoint (`https://{account}.services.ai.azure.com/api/projects/{project}`), or the account endpoint plus `AzureOpenAI:ProjectName`. `EVAL_MODEL_ENDPOINT` and the deployment endpoint secret use the same project endpoint. The configured `AzureOpenAI:ReasoningEffort` is now applied to every turn (low for greetings). The app identity's Bicep role on the Foundry account is now **Foundry User** (formerly Azure AI User), which the project Responses endpoint requires; **Cognitive Services OpenAI User** covers only the account's OpenAI endpoints. Existing deployments and the evaluation identity need that role before switching to the project endpoint.
- Each conversation stores its serialized `AgentSession` (the chained previous-response ID) and a host-owned UI transcript under the owner's directory. The chain advances only after a successful turn, so Stop or a failure never leaves unanswered tool calls; an expired chain resets to a fresh model context. The service retains stored responses (about 30 days); deleting a conversation removes local state only.
- Scheduled-job compaction now starts a fresh model context every 20 runs; the run prefix carries the latest bounded result forward.
- The container image no longer bundles the Copilot CLI or the OpenTelemetry collector sidecar: the host already exports its traces, including Agent Framework spans (`AzureFinOps.AI.Agent`), directly to Azure Monitor.
- Simplify the model-facing tool surface from 21 tools to 17 tools, all registered directly on every run. `QueryAzure(url, method, body, query)` covers every HTTP evidence read, and `ApplyAzureChange` every approved ARM write.
- Replace bulk envelopes with parallel `QueryAzure` calls and multi-line `url`: up to 50 same-kind GETs (for example one per region) are one tool call, run at most 4 at a time, each cropped by the same `query`, with failed lines reported as a partial result. Compute capacity guidance reads every region's quota, including the Spot `lowPriorityCores` pool, from one Resource Graph `QuotaResources` query. Cost Management `/query` and `/forecast` remain serialized per tenant by the host, retry once after a service cooldown, and stop after a final 429 for the rest of the turn.
- The system prompt limits lookups to what the question needs (no documentation research for unrequested caveats; read a returned Learn article rather than rewording the search).
- Move totals, shares, rankings, comparisons, token-cost estimates and running totals into model-authored `query` expressions (`Sum`, `GroupBy`, `Math.Round`, running totals) and url-less calculations instead of helper calculators.
- Replace live-evaluation case `552f572706ca51cd` with `3c99447cf28f786c`, covering English calculation through a `QueryAzure` query rather than mental arithmetic. The judge treats url-less calculations, and one repeat with `query` after a schema-only response, as expected rather than waste.
- Switch the default agent model and live-evaluation agent/judge models to `gpt-6-sol` version `2026-09-22` and keep the maintainer runbooks under `.github/skills/`.

### Removed

- Remove `GitHub.Copilot.SDK`, the bundled CLI runtime, `RuntimePolicy`, SDK call-id admission, deferred tool metadata and the OTel collector configuration. Conversations created by the SDK runtime are not listed after upgrading; their files remain under `$COPILOT_HOME/.copilot/session-state` until an operator deletes them.
- Remove the former stored-result query, cost calculator, amount comparison, token-estimate and standalone operation-status helper tools.
- Remove `QueryAzure`'s bulk-call envelope, inline projection object, caller-selected page cap, public-web grep and caller-selected parallelism knobs. Paginated ARM, Graph and Retail GETs now follow same-origin continuation links up to the fixed 10-page host cap.
- Remove the unused `jq` and `sqlite3` CLIs from the runtime image; no shell tools remain to call them.
- Remove `ProtectedTool`, the host-side result database, `OperationStore`, the `/api/operations` endpoints and the application approve/reject endpoints. Tools run unwrapped under Agent Framework, tool events and evidence come from the streamed function call and result contents, and write approval is Agent Framework's own. An in-memory SQLite result store existed briefly before release and was dropped: under 2.5 MB SKU pages its capped store evicted responses a later join needed, and quadratic share queries over 14,000-row cost results hit its deadline.
- Remove host-side credential screening and redaction (`SensitiveContent`) from chat, jobs, tool arguments and returns, SSE, transcripts, generated scripts and uploads; recognizing and refusing secrets is left to the model. Under concurrent multi-URL reads, its regular expressions timed out over 2.5 MB SKU responses and replaced whole tool results with `[REDACTED]` while still reporting success. Browser telemetry scrubbing and public evaluation-report redaction are unchanged.

### Fixed

- Stop pricing answers from spending web searches on unit conversions and API documentation. In gate run c0cc7df, the Azure OpenAI token comparison was accepted as grounded and complete but rated inefficient: after one batched Retail Prices lookup, gpt-6.1-sol sent the hosted web search `calculator: 0.0025*1000` to convert per-1K to per-1M rates. Locally, the 3-tier estimate opened with web searches for the Retail Prices API's own Learn documentation. The Retail Prices guidance now says its entry is the complete contract, so the model starts with the price request itself, and that units are converted in the same query that selects the rows (per-1M from `1K` token meters as `retailPrice * 1000`, monthly from hourly × 730). The system prompt states that token meters are priced per 1K and that web search is never a calculator or unit converter (no `calculator:` queries). The same local probe's first query also failed: the API filters on `priceType`, but each returned item carries that value as `type`, so `x.priceType` needed a corrective second call. Both pricing texts now name the returned field.
- Stop the live gate from failing a correct answer over one nearly free stray call. The efficiency score counted the single 1.36-second web search above as doubling a one-call answer's calls (score 2, fail), although it added about 3% to the elapsed time. A single avoidable call or round that adds less than a tenth of the elapsed time now scores 4. Repeated waste, and a single stray call that costs real time, still fail.

Because meter names are not derivable from the ARM SKU — `Standard_ND96asr_v4` meters as `ND96asr_A100_v4` — a vocabulary filter matching zero rows is now dropped automatically, re-queried on the structural filter alone, and reported, so the tool can never hand back an empty table. Measured on the GPU comparison: **46.6 s / 2 tools with invented rates and a false "Retail API rows were unavailable" basis line → 22.7 s / 1 tool quoting the API's own $27.197 and $13.960**, with no web fallback. The 3-tier estimate now sources its P30 price ($135.17) from the API instead of a guessed assumption, and Foundry comparisons return the correct Standard Global rates with no model names left in the codebase.
- **`azd up` can now provision the custom domain end to end.** A new `AZURE_CUSTOM_DOMAIN` setting creates an Azure DNS zone with every record already in place — apex A, `www` CNAME, the `asuid` ownership TXT, and the hardening records that were previously missing entirely: a **CAA** record pinning issuance to the three DigiCert issuer domains that App Service managed certificates actually chain to (without one, any CA on earth may issue for the domain), plus a **null MX + `v=spf1 -all` + `p=reject` DMARC** set so a domain that sends no mail cannot be spoofed. Nameservers are surfaced as `AZURE_DNS_NAME_SERVERS` for the registrar. An optional `ENABLE_DELETE_LOCKS` puts a `CanNotDelete` lock on the zone for long-lived domains (off by default, so `azd down` still tears an evaluation environment down cleanly). Hostname binding and certificate issuance deliberately stay in the runbook — they are strictly ordered around DNS propagation, which a single ARM deployment cannot wait on.
- **Outside-in availability monitoring.** A standard App Insights web test now probes the public URL every 5 minutes from five regions, with a Sev-1 multi-location alert. This closes a real blind spot: every previous alert was a scheduled KQL query over `requests`, which can only fire when the app is _already serving traffic_ — if DNS broke, the certificate lapsed, or the site was hard-down, zero requests arrived and none of them could ever fire. The test also asserts `SSLCertRemainingLifetimeCheck: 7`, so it doubles as the certificate-expiry alarm that was previously absent (managed-cert auto-renewal fails _silently_ if DNS ever stops resolving to the app).
- **`.github/prompts/migrate-tenant.prompt.md`** — a reversible, two-phase runbook for rebuilding the stack in another Azure tenant and cutting the custom domain over without a broken window. Documents what provably cannot migrate (the Entra app registration, `/home` state, telemetry history) and keeps rollback at one DNS TTL until the final step.

- **Scheduled jobs — a recurring prompt that runs in the background, even with the browser closed.** A new "Scheduled jobs" pane below Conversations lets an Azure-connected user save a prompt + cadence (every 15 min / hourly / daily / weekly); the backend `JobScheduler` runs it as a normal agent turn in its own dedicated conversation, so every run's answer (text, tables, charts) is browsable by opening the job. Built for the capacity-hunting use case — "check H200 spot capacity + quota across all my subscriptions and regions every 15 minutes and tell me the moment it's deployable" — but works for any standing task (daily cost report, anomaly sweep, license audit). Background auth is delegated-only: each run re-mints the user's Azure/Graph/Log Analytics/Storage tokens from the persisted MSAL refresh token (no app permissions, no admin consent — the job can never exceed the user's own RBAC), and pauses itself with a "reconnect Azure" status if the refresh token dies. Runs share the one-turn-per-session gate with live chat (a job can never race a chat turn), preserve the user's active conversation (a 3 AM run won't hijack which chat you see next), and keep the same tool surface as chat (writes allowed, **DELETE still blocked**). Caps: 3 active jobs per user; sub-daily jobs auto-expire after 7 days, daily/weekly after 90; a job auto-pauses after 5 consecutive failures. `GET/POST /api/jobs`, `POST /api/jobs/{id}/run|toggle`, `DELETE /api/jobs/{id}`. The pane is built to feel alive: “+ New job” opens a centered **modal sheet** (blurred backdrop, Esc/backdrop close) with one-click **templates** — GPU hunt & reserve (checks quota + capacity every 15 min and, when deployable, **secures it by creating an on-demand Capacity Reservation via ARM PUT**, idempotent with an explicit bills-while-held warning and a pause-and-cleanup instruction), daily cost digest, anomaly watch, budget guard, idle resource sweep, Advisor watch — plus cadence pills, a **"Run immediately, then repeat on the schedule" checkbox** (default on: the first result lands in the job's conversation within a minute; unchecked: the first run waits one full interval), and an autofocused prompt; rows show a **live countdown** ("next in 12 min", 30 s ticker) and status animations — breathing blue = armed, pulsing green = running now, pulsing red = failed/reconnect Azure, gray = paused; clicking a job that has never run shows a "no runs yet — ▶ runs it now" nudge instead of doing nothing; the list auto-sorts (running → failing → soonest next run → paused) so it scales past a handful of jobs; the header shows "N active · M failing" and collapses the pane instantly (sticky per browser); statuses refresh on tab-return plus a 45 s background poll, so returning users immediately see what ran while they were away.
- **A scheduled job can now run on a custom cadence, not just the presets.** Alongside the Every 15 min / Hourly / Daily / Weekly pills, an "or run every \_\_\_ min" field accepts any interval from **1 minute to 30 days** — so "every 1 min" (near-real-time monitoring), "every 45 min", "every 3 h" (180), or "every 2 d" (2880) are all one field away. The pills are now shortcuts that fill the same field; rows render the custom cadence in the largest whole unit ("every 45 min", "every 3 h", "every 2 d"). Out-of-range values are rejected inline (create/save disables with a hint) and by the API. (1 min is the scheduler's tick cadence — the fastest it can fire; a run never overlaps its previous one thanks to the per-session turn gate.)
- **Edit a scheduled job in place.** Every job row now has a pencil (✎) that reopens the same modal prefilled with the job's name, prompt, and cadence — in edit mode the template picker and "run immediately" checkbox are hidden, the title reads "Edit scheduled job", and the button saves via a new `PATCH /api/jobs/{id}` (name / prompt / intervalMinutes each optional, validated the same as create). Changing the cadence recomputes the job's expiry (7 d sub-daily / 90 d daily+weekly) and re-arms the next run one interval out. Previously a job could only be created or deleted, so fixing a typo or retuning a cadence meant delete-and-recreate (losing the run history).
- **A failed job run is now visible at a glance.** A job whose last run errored shows "last run failed · next …" in red on its row (instead of the generic cadence line), so a broken job stands out without opening it — the header already counts "N failing".
- **SSE keepalive pings during long silent phases.** A turn can emit no bytes for minutes while the model generates a large tool argument (an 800-line deck or script) between the last reasoning delta and `tool_start`. Intermediate proxies (App Service front end, ~4 min idle) and the client's 3-minute inactivity watchdog would drop a perfectly healthy turn. The backend now emits a `{type:"ping"}` every 20 s while awaiting completion; the client ignores it.

- **A job's conversation is now a run log, not a chat.** Opening a scheduled job's conversation shows its runs updating live (a follow loop keeps the view fresh while runs land server-side — previously the view silently froze while runs piled up on disk) with a job bar instead of a composer: **Build deck**, **Summarize runs**, **Edit job**, **New chat**. Free-form typing into a run log muddled the history and silently steered future runs — editing the job's prompt is now the explicit way to steer it, and sidebar titles read "⚙ Job · {name}" so job threads are unmistakable.

Actions are now a hover overlay on the right edge — the text owns the whole row until you hover (keyboard focus reveals them too). The status line got richer: `every 15 min · ran 2m ago · next in 13 min` — cadence, last run, and next run at a glance; failures read `failed 2m ago · next in X` (the failure timestamp doubles as the last-run time), and the countdowns/ago-times tick live. The row tooltip now includes the total run count.
- **Job templates now lead with capacity** — the single most common customer complaint. The grid starts with **"Check capacity of X"** (read-only: where is this VM size deployable right now, across all my subscriptions and regions — every 15 min) and **"Reserve X when available"** (the generalized GPU hunt: when the size becomes deployable with quota headroom, secure it via an on-demand Capacity Reservation — idempotent, cost-warned). A new **"1-min test"** template (one-sentence USD consumption report, every minute) lets anyone see how scheduled jobs work within a minute of creating one.
- **The job row's pause control is now a proper on/off switch.** ▶ (run once now) sitting next to ⏸ (pause the schedule) read as contradictory transport controls — like a media player showing play and pause together. The schedule state is now a small toggle switch (blue = armed, gray = paused) that can't be misread, stays visible on paused rows as the state indicator, and announces itself to screen readers as a real `switch`. ▶ keeps its "run once now" meaning.
- **Local BYOK can pin its token tenant.** New optional `AzureOpenAI:TenantId` setting — set it when the az CLI's default account lives in a different tenant than the Azure OpenAI resource (previously every local AI turn failed with "Token tenant does not match resource tenant" and the only fix was switching the CLI's global default).
- **Deleting a job or a conversation is now immediate — no confirm dialog, and optimistic.** The × removes the row instantly (before the server round-trip), so the button always feels alive; if the server call ever fails, the next list refresh restores the row. Deleting a job keeps its conversation and run history.
- **Each right-sidebar pane (Agent, Conversations, Scheduled jobs) can be collapsed to its header** via a large rotating chevron, with a smooth slide animation (the content row glides shut instead of snapping) — collapse two and the third takes the whole sidebar, so you can focus on one area (e.g. a long jobs list or a deep tool-call trail). Collapse state is remembered per pane.
- **The Scheduled jobs pane got a little bottom breathing room** so the last job row isn't cramped against the sidebar's bottom edge.
- **`QueryGraph` now allows write methods (GET/POST/PUT/PATCH); `DELETE` stays blocked.** Previously GET-only. This aligns Graph with `QueryAzure` so the agent can act on Microsoft Graph (e.g. group/license management) when the tenant has consented to write scopes — the standard read-only consent tiers still cause Graph to return 403 for writes, which the tool surfaces rather than retrying. The delete prohibition is unchanged and remains the product's hard guarantee.

### Fixed

- **Generated presentation cards now provide an in-app Preview instead of download-only UX.** Preview fetches the existing owner-checked `?inline=true` artifact, removes scripts and external resources, lays every slide out in a vertically scrollable static view, and renders it in a fully sandboxed modal iframe. The deck cannot access the app's cookies, storage, DOM, or authenticated APIs; Download remains a separate action, and restored deck cards get the same preview.
- **Fast send/remove actions can no longer resurrect attachments or create ghost uploads.** Sending immediately after choosing a file raced `uploadFiles`: the send path removed the image chip, then the upload callback wrote its result back to the stale array index, making the chip reappear; removing an in-flight upload could similarly update the wrong chip and leave an invisible server-side file attached to the next turn. Sends now wait for upload settlement, callbacks locate chips by stable `uid`, abandoned uploads delist their eventual server `fileId`, and blob thumbnail URLs are revoked only after Vue unmounts the image (eliminating `net::ERR_FILE_NOT_FOUND` console errors). Successful upload deletion now returns an explicit `200 { removed: true }`; the integrated Chromium browser reported an otherwise completed empty `204` response as `net::ERR_ABORTED`, failing the application's zero-network-error invariant.
- **Image attachments no longer fail with “The image data you provided does not represent a valid image.”** The app had upgraded to `GitHub.Copilot.SDK` 1.0.11 while retaining a stale `<CopilotCliVersion>1.0.70</CopilotCliVersion>` workaround from SDK 1.0.7. Text and tools still worked, but the mismatched runtime mishandled valid PNG/JPEG path attachments and every vision turn completed with no answer. The override is removed so SDK 1.0.11 supplies its compatible, now-published CLI 1.0.79 runtime.
- **Admin consent failed for every fresh deployment because three requested permissions were not delegated scopes.** `setup-entra-app.ps1` declared the Microsoft Graph `Organization.Read.All` and `Group.Read.All` **appRole** GUIDs — plus a Log Analytics `Data.Read` GUID that does not exist on that API — as `type = "Scope"`. Entra validates a consent request atomically, so consent failed for the whole app and no service principal was ever created, blocking "Connect Azure" in any tenant that requires admin consent. The correct delegated `oauth2PermissionScopes` ids are now used, every id is additionally re-resolved by value from the resource's published scopes at run time (falling back to the constant only when the resource service principal cannot be read), and a failed permission update now exits non-zero instead of being swallowed. The `postprovision` redirect-URI patch likewise re-reads the app and fails loudly when a callback did not apply, instead of printing a warning that scrolls past and surfaces later as `AADSTS50011`.
- **A "cheapest region" answer could quote Spot prices as on-demand.** `priceType='Consumption'` also returns Spot and Low Priority rows, so ranking a flat list by price surfaced Spot ($17.52/month for a D4s_v5) where the question meant standard pay-as-you-go ($140.16/month). The projection now round-robins across `meterName` groups so the ordinary on-demand meter is always visible regardless of price, comparisons are constrained to a single meter, and the agent states which meter it quoted.
- **XLSX inspection no longer pays repeated pandas startup or a second aggregate round.** Workbook operations now run directly through `openpyxl`; `workbook` mode returns bounded count/sum/min/max/mean summaries for numeric columns on every sheet. A question such as “which sheet contains snapshots and what is their total monthly cost?” is answerable from one file-tool call instead of `workbook` → `aggregate`, while the checked-in workbook fixture is now genuine OOXML rather than legacy OLE bytes under an `.xlsx` extension.
- **Crawl scoring no longer takes 56–120+ seconds.** The original sweep made 19 independent model/tool round trips; the first server-side consolidation still queued 12 low-cost metadata GETs behind the global Cost Management query semaphore and then paid separate `ReportMaturityScore` and `SuggestFollowUp` rounds. Metadata now uses verified full concurrency with one attempt, Cost Management `/query` is unnecessary for MTD because budgets expose exact current spend, and score/follow-up side effects happen in the evidence tool. A low-reasoning experiment was measured and reverted because it was slower (24.51 s vs 22.14 s) and offered no quality-safe gain.
- **Long markdown tables no longer split at Azure identifiers.** The stream commit path tried to “repair” missing sentence spacing by replacing every `.<uppercase>` with a paragraph break. Resource names such as `MDE.Linux`, versions such as `v1.2.3`, and hostnames such as `api.Contoso.com` were corrupted; inside a table this ended the regex match and left the remaining rows as raw pipe text. The unsafe punctuation rewrite is gone. Verified on a fresh stream with all identifiers preserved and all rows rendered.
- **Page-load warmup and transcript replay no longer race into HTTP 500.** Both could call `ResumeSessionAsync` for the same persisted session concurrently, producing `Session '…' is already tracked by this client`. Transcript loading now shares the per-user session gate and reuses a tracked live session; repeated reloads return 200 and restore the transcript.
- **Disconnect and revoke now remain disconnected.** Both routes cleared in-memory/session tokens but left the `finops_id` cookie, so hydration restored `azure_user` and the refresh token on the very next request. Disconnect now removes the cookie while retaining the encrypted identity record for an explicit reconnect; revoke removes both cookie and identity record and forces a fresh consent screen. Logout still clears the full Entra identity and assigns a new anonymous chat user.
- **Creating a job with “Run immediately” now auto-opens its run log.** Explicit run-now and edit+run-now already watched for the scheduler-created session, but initial creation omitted that call. The new job now opens the same dedicated session and refreshes until the first answer lands; the transient “running” notice clears on convergence.
- **The old-snapshot waste check no longer fails Resource Graph parsing.** It projected away the `created` column and then sorted by it twice. Sorting now occurs before projection and the final result uses `take`; the full eight-pattern idle scan completes with no subquery error.

- **A completed answer can no longer remain hidden behind a silently stranded SSE reader, missing terminal frames, or a late Stop click.** Chromium can leave `response.body.read()` pending after the server has finished and persisted the answer, with no EOF, delta, or `AbortError`; the UI then stays on a bare AI avatar indefinitely. After 10 seconds without SSE bytes, the client now checks the authoritative per-session turn gate; if the turn is no longer active and the matching answer exists on disk, it aborts only the zombie reader and reloads the transcript. A normal EOF with no renderable frames also checks the persisted tail once before showing an empty-turn warning. Abort intent is explicit: reset/logout uses `discard`, an unrequested `AbortError` follows recovery, and only the Stop button requests `stop`. The stop endpoint distinguishes `{stopped:true,alreadyCompleted:false}` from a late race `{stopped:false,alreadyCompleted:true}`; the latter reloads the completed answer instead of replacing it with “You stopped this response before it finished,” while an active stop still wins even if partial text was already persisted. Verified with deterministic browser cases (stranded completion, empty terminal EOF, late Stop, active Stop with partial persisted text) and a clean real 3-tier starter, which rendered its full answer/chart with no blank response.
- **Trivial acknowledgements now use words instead of an emoji-only reply.** The one-round-trip directive still forbids tools, tables, headings, lists, and charts, but now requires one short text sentence; `ok` was returning only `👍`, which violated the UI test contract. Verified with a real model turn: “Understood—what would you like help with?” and zero tools.

The default hostname (and any other non-canonical host) now returns `X-Robots-Tag: noindex, nofollow`, driven by the existing `PUBLIC_SITE_HOST` setting; `www.` counts as canonical-equivalent since it already 301s to the bare domain. Deployments that don't set a canonical host are unaffected.

ARM creates siblings in parallel, but a Cognitive Services account serializes control-plane operations — so the project raced the deployment and the whole provision aborted with `RequestConflict: Another operation is in progress on the resource`. Adding `dependsOn: [modelDeployment]` orders them. Reproduced on a real deployment and confirmed fixed on the retry.

Entra rejected the update, the hook printed a warning, and `azd up` continued as if healthy — leaving the app with only a `localhost` redirect URI, so every sign-in on the real hostname would fail. The lines are now joined before parsing and hard-cast to `[string[]]`. The hook also never registered the `/auth/microsoft/adminconsent/callback` URIs despite that being a live route, which broke the admin-consent flow; both are now included.

The hook now prunes those generated directories first (the Dockerfile rebuilds them all inside the image), matching the cleanup the manual checklist in `deploy.prompt.md` already mandated.

Verified in the live browser with the same chart and viewport — SVG width 150→730px, overlap eliminated.

The orphan kept running and kept billing, while the alert (which only ever references the current test) silently stopped covering it. Observed live: two tests in one resource group, one probing the default hostname with no alert attached. The name is now keyed on the App Insights component alone, making the URL an in-place update.

Panes now share the sidebar by fixed proportion and the tool list scrolls inside its own pane.

Run logs now live only under their job row (deleting the job makes its history reappear in Conversations, so nothing is lost), and deleting any conversation server-side detaches it from any job that referenced it — the job behaves as "never ran" and creates a fresh log on its next run.

It now opens the job's edit/detail sheet — and that sheet gained a **"Run now after saving"** option, so you can run a job straight from it. Triggering a run (that option, or the ▶ button) now **auto-opens the run's conversation** and refreshes it until the answer lands, so you can actually watch the run.

Paused rows now read "paused" (keeping the "last run failed" / "reconnect Azure" reason when relevant); only enabled jobs show a next-run countdown.

The toggle endpoint now rejects a resume that would exceed the cap, and the row shows "Limit reached — max 3 active jobs. Opening a new job now always starts from a clean slate, and all four close paths (Cancel, ×, Esc, backdrop) clear the edit state.
- **A generated table (or any answer) no longer flashes on screen and then disappears.** The chat wiped the streamed answer buffer on every `tool_start` after text had streamed — a heuristic meant to drop mid-turn narration before the real answer. But the model calls `SuggestFollowUp` (and sometimes `ReportMaturityScore` / `PublishFAQ`) _after_ the final answer, so that wipe deleted the just-rendered table, leaving only a follow-up chip (the answer was still in the persisted transcript, which is why it reappeared on reload). Those post-answer tools are now excluded from the wipe, and a safety net restores the last wiped text if a turn ends with an empty buffer (which also fixes chart-only answers losing their lead-in sentence).
- **A blank white page after a deploy (seen in Edge) is fixed.** `index.html` was served `no-store` but the content-hashed `/assets/*.js|css` bundles carried no cache header, so a browser could serve a cached `index.html` from the previous deploy that referenced the _old_ bundle hashes — which 404 after redeploy, leaving a white screen until a hard refresh. Static file caching is now explicit: hashed `/assets/*` are `immutable` (cached a year), while `index.html` / `/` are `no-cache` (always revalidated), making deploys atomic for the browser.
- **A severed stream on a long-running turn no longer gets stuck showing one (or two) permanent "⏳ Reconnecting" banners.** On a big turn — "go through all regions × all subscriptions" — the CLI persists nothing until the final answer, so the client's 3-minute recovery poller gave up while the turn was still running (the backend allows turns up to 15 min); worse, early poller exits left the banner on screen **and** freed the recovery lock, so the next window-focus/visibility event spawned a second poller that stacked a **second** banner, neither of which ever cleared. Recovery is now robust: the poll deadline covers the backend's full 15-minute turn budget (3 s→10 s backoff), the banner is a single deduped instance that is cleared on **every** exit path (early return, recovery, timeout, throw), the send-catch fires recovery **fire-and-forget** (so `send()` resets the composer immediately instead of blocking up to 15 min and double-posting), and on genuine timeout the dead banner is replaced with an actionable "Connection lost — Retry" message. Verified live: a real `ERR_CONNECTION_RESET` mid-turn shows **exactly one** banner that survives 36 focus/visibility events with zero console errors.
- **Returning to an empty or already-answered conversation no longer shows a phantom "⏳ Reconnecting" notice.** The tab-return / window-focus reconcile treated any view that didn't end in a non-empty assistant message as "answer missing", so a brand-new/empty session (or one ending in a system notice) flashed "Reconnecting — your last answer is still being generated" and polled for 3 minutes even though no turn was ever in flight. Reconcile now only recovers when the current view has a genuinely unanswered user turn (a last user message with no real answer after it); a new `assistantTurnHasOutput` helper counts text, a chart, a generated deck/script, or completed tool calls as a delivered answer (so chart-only answers no longer false-trigger), and the recovery poller bails immediately on a blank prompt.

They're now kept stream-local and only mirrored to the shared refs while that session is the active view.
- **Restored conversations get their follow-up buttons back, and expired artifacts show a clear state instead of dead links.** Transcript replay now re-derives the follow-up action buttons from the persisted `SuggestFollowUp` result (live turns already keep them), and deck/script cards whose 30-minute in-memory artifact has been swept (or lost on restart) render an "Expired — ask to regenerate" hint instead of a Download/Copy button that 404s.

- **Starting a new conversation no longer wipes a background-streaming conversation's tool list.** `newSession()` cleared every session's live tool/chart buckets; it now drops only the current view's (and the `__pending__` sentinel's).
- **Concurrent-turn rejection ("busy") no longer leaves an orphaned user bubble.** When the server rejects a second prompt sent to a still-running session, the optimistic user bubble is removed and its text is returned to the composer for an easy retry.
- **System notices (resume / busy / recovery) render as muted centered pills** instead of masquerading as AI answers with an avatar.
- **Copying a generated script now shows a "Copied ✓" checkmark** for ~1.5 s on the exact button clicked.
- **Deleting a conversation now asks for confirmation** — the small `×` is an irreversible server-side delete and a mis-click shouldn't silently destroy a thread.
- **Per-session context-dedup dictionaries are pruned on session delete** (they previously grew unboundedly over the process lifetime), and each mounted chart's `ResizeObserver` is now disconnected on wipe/unmount instead of observing detached DOM forever.
- **Dead model-selection leftover removed** — the frontend no longer tries to auto-pick an "opus" model from `/api/models`; the backend always chats with its configured deployment and ignores the request's `model` field.

Styling is scoped to the panel (`.reasoning-md`) and kept compact + muted so headings/lists/code/tables don't blow up the small rolling-window box, and the rendered HTML is wrapped in a single inner block so the "pin newest lines to the bottom" effect still works. Verified live: a `**bold**` reasoning header rendered as `<strong>` with correct line breaks, no console errors.

Verified live: pinned through thinking-panel growth 641→747px, no yank while scrolled up mid-stream, pill jump + re-follow, transcript restore lands at bottom.

### Fixed

- **Backgrounding, minimizing, or leaving the window no longer loses the answer.** The backend keeps generating and persists the turn when a client disconnects, but the UI could come back to an empty response or a spurious “Connection lost”. Recovery is now bulletproof and non-destructive: (1) a severed stream recovers by polling the persisted transcript for THIS prompt’s answer (tail-match — instant if it landed while away) and repainting, with a brief refinement watch so mid-turn narration converges to the final answer; (2) a silently-dead “zombie” stream is detected on tab return purely from SERVER state (answer persisted but undelivered one confirm-tick later → abort + recover) — never from client-silence timers, which would kill healthy reasoning pauses; (3) `GET /api/sessions/{id}/messages` now serves anonymous users too (still IDOR-gated per-user), which recovery depends on. Verified live: sever mid-turn → answer recovered; healthy hidden/visible toggle → completes untouched.

### Added

### Fixed

- **Chat input box now grows with multi-line content.** The auto-grow logic set the textarea height from `scrollHeight`, but `.input-field { flex: 1 }` inside the column `.input-wrapper` (flex-basis:0) made the flex layout ignore that inline height and collapse the field to one line. Changed to `flex: 0 0 auto` (width preserved via the wrapper's `stretch`), so the field expands 24px→400px then scrolls (`overflow-y:auto`). Verified live: 1 line=24px, 8 lines=180px, 60 lines=400px+scroll, cleared=24px.
- **Entra account switch no longer leaks the previous account's state.** Signing in with a different Microsoft account on the same browser session used to hand the new account the previous account's ARM/Graph/Log-Analytics/Storage tokens, consent tiers, and active conversation (the anon→Entra in-memory migration also ran on Entra→Entra switches, and per-resource session tokens were never purged). The OAuth callback now detects the OID change, skips the migration, purges every token/tier belonging to the previous account, and repoints (or drops) the `finops_id` identity cookie so hydration can't resurrect the old identity.
- **Base-tier users no longer fire doomed token exchanges on every message.** Every chat request attempted refresh-token exchanges for Graph, Log Analytics, and Storage even when the user only consented to base ARM — each a guaranteed HTTP 400 at `login.microsoftonline.com` plus up to three wasted Entra round-trips of first-token latency per message. `SessionTokenStore` now gates refresh attempts on the consented-tier list (all add-on tiers are recorded in `graph_tier` at consent time, incl. loganalytics/storage) and applies a 15-minute backoff after a failed add-on exchange. Failed exchanges also log the AADSTS `error`/`error_description` instead of silently returning null. _Note: users who consented to Log Analytics/Storage before this change need to re-click the add-on button once (their persisted consent list predates the tier markers)._
- **Streaming no longer freezes when the browser tab is backgrounded.** The typewriter effect drained text via `requestAnimationFrame`, which browsers fully suspend in hidden tabs — the answer looked stalled and crawled at ~600 chars/s after refocus. Text now renders synchronously while the tab is hidden and the pending animation queue is flushed on `visibilitychange`.

### Fixed

- **Stale-session recovery for chat turns — no more hard error _or_ silent hang.** Two related gaps in the SSE chat path when the CLI had evicted a session between turns (the first confirmed via stack trace at `ChatEndpoints.cs`): **(1)** the per-turn effort switch (`session.model.switchTo`) ran _before_ the streaming subscriptions and threw `Session not found` uncaught, surfacing a raw error to the user; **(2)** the `SendAsync` recycle reassigned the session handle but left the SSE subscriptions bound to the _dead_ one, so a recycled turn generated server-side yet never streamed to the browser. Both now recover: the effort switch recycles **before** subscriptions are wired, and the `SendAsync` path detaches and **rebinds** the subscriptions (`WireHandlers`) onto the live session, re-announcing the session id so the frontend keeps streaming into the right conversation. Verified: happy-path streaming (text, tool calls, chart, first-event timing, completion) is fully regression-clean through the refactored subscription wiring; the recovery branches are correct-by-construction and reuse that same proven wiring, but the underlying staleness is a non-deterministic race (idle-disconnected sessions transparently auto-reconnect from disk) that could not be force-fired in re-tests.
